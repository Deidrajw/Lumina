## Scope and interpretation
The user-provided `wellness-tracker.html` matches GitHub's root `index.html` byte-for-byte after adding its final newline. Source code inspection plus Chromium isolated smoke testing were conducted. Browser navigation was network-restricted: tests used `page.set_content` with **mocked localStorage**, offline font fallback, and fictional data. **Real IndexedDB round-trip, Cloudflare live validation, iPhone Safari, camera, share, PDF output and cross-origin restore were NOT TESTED.** Never mark these Verified. Results are PASS (isolated automated), FAIL (isolated automated), CODE-CONFIRMED, UNTESTED or BLOCKED. A complete end-to-end signoff requires testing on a proper origin/device.

## Overall direction
Lumina's premium visual identity (deep plum, mauve, Instrument Serif and Manrope), product-centred data relationships and six-section architecture are strong. Preserve them. PRIORITY is data trust and core stability, then accessibility/readability and progressive disclosure; no broad redesign or feature expansion before approval.

## P0 — data-loss / privacy findings
- **LUM-BUG-001 (CODE-CONFIRMED)**: `exportData()` includes IndexedDB photos under `_photoBlobs`, but `importData()` only restores `KEYS`, not those blobs. Restore may strand photo metadata. Require clean-origin export/import full photo comparison, error handling, idempotence.
- **LUM-BUG-010 (CODE-CONFIRMED)**: In editing an existing symptom/concern, `removeSympPhoto` / `removeConcPhoto` immediately delete the IndexedDB blob, before parent Save. Tapping Cancel can preserve the old record referencing a deleted image; pending newly attached photos can be orphaned on Cancel. Stage all photo changes and commit only on successful parent save.
- **LUM-BUG-011 (CODE-CONFIRMED)**: `clearAllData()` clears localStorage `KEYS` but does not clear the IndexedDB image database. “Everything wiped” is misleading and potentially privacy-sensitive. Clean up all stores and verify; do not change existing personal data without explicit confirmation.
- **LUM-BUG-012 (CODE-CONFIRMED)**: `saveProgressPhoto()` saves base64 images directly to localStorage and ignores `save()` failure; it clears photo state, logs and closes even if a quota error prevented persistence. Preserve form/photo on failed save and unify with IDB.

## P1 — correctness/security and broken flows
- **LUM-BUG-013 (FAIL, isolated automated)**: Vault > Data Cleanup with populated fictional items shows `Display error — _invSearchFocused is not defined`. `renderDataCleanup()` accesses undeclared variable after constructing output; empty early exit masks bug. Fix and retest populated/empty.
- **LUM-BUG-014 (FAIL, isolated automated)**: HTML string from a fictional concern's `title` executed an `img.onerror` handler when rendered in Body; user/imported fields interpolate into `innerHTML` unsafely. Escape imported and typed content or use `textContent`; test hostile records across every view and import.
- **LUM-BUG-015 (CODE-CONFIRMED)**: `today() = new Date().toISOString().slice(0,10)` uses UTC date while weekday logic is local; user in Toronto can log the wrong date during evening. Change date helpers consistently and test DST, evening boundary, streaks and reports.
- **LUM-BUG-019 (CODE-CONFIRMED risk; UI PASS)**: Demo symptom-save UI correctly blocks updates, but low-level `save()` has no preview-mode write guard; direct call mutated real mocked storage during preview. Audit all mutators, migrations and deletes; centralize write boundary. **No end-user UI leak was demonstrated.**
- **LUM-BUG-020 (CODE-CONFIRMED)**: `saveManualCapture()` attaches captured photo as inline base64 to product records instead of the shared IDB system, posing quota and portability risks. Standardize image storage.

## P2 — UX and release honesty
- **LUM-BUG-017 (FAIL, isolated automated)**: Escape closes lightbox/product page only, not an open symptom bottom sheet. Audit all 39 modal/backdrop elements; preserve form draft/confirm unsaved edits.
- **LUM-BUG-016 (CODE-CONFIRMED)**: Smart Capture landing promises “AI reads the label / extracts…” while `extractProductInfoFromImage()` returns null; actual `runOCR()` correctly says OCR disconnected/manual. Update landing and help text to manual photo capture until backend is real.
- **LUM-BUG-018 (CODE-CONFIRMED and screenshot)**: App v0.9.4 What's New uses `LUMINA_CHANGELOG[0]` for v0.9.3 and August 5, 2026. Fix version provenance and banner.
- **LUM-BUG-021 (CODE-CONFIRMED)**: `saveInv()` logs entire saved product including possible prescription details/notes/photos to console. Remove/redact sensitive debugging logs.
- **LUM-BUG-022 (CODE-CONFIRMED)**: Metadata text contrast approximately 2.75:1 for dark card tertiary token and 2.67:1 for light tertiary token; bottom nav labels 9.5px, some header targets 32–36px and viewport maximum-scale=1. Improve essential legibility, user zoom and tap areas.
- **LUM-BUG-023 (UX REVIEW, Safari untested)**: Populated Today/Insights are long and dense with many equally weighted reminders/cards. Reduce visible items, prioritize top insight/actions, collapse low-priority detail, preserve established premium style.
- **LUM-BUG-024 (CODE REVIEW)**: One approximately 11,370-line HTML with 487 distinct function declarations, ~291 inline event handlers and duplicate `rerenderActiveTab` declarations increases regression risk. Incremental modularization only after stabilization.

## Proposed staged plan (awaiting approval)
**Phase A — Protect data:** reversible image staging and Cancel semantics; export/import complete photo restore with clean origin; unify photo stores; honest quota errors; complete Clear All Data. **Release gate:** no lost photo on Save/Cancel/Delete/Refresh/Import, real-origin verified on Safari.
**Phase B — Correct broken/unsafe flows:** Vault Cleanup error; escape all text; timezone-safe date calculations; central demo write guard; redacted logs; run global-search-to-edit, reorder, supplement template tests.
**Phase C — Polish existing UX:** clarity/contrast/touch size, modal Escape/focus/cancel, fewer default cards in Today/Insights, grouped Vault editor, honest capture and current version banner.
**Phase D — Release hardening:** verify live Cloudflare URL/build/branch previews, PWA/Safari/caching, private backup migration, beta release regression and rollback. No production merge without user approval.
